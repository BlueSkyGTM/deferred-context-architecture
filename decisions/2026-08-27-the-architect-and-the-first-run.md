# The architect, and the first run

Pass C, and the mandate for the first thing this method has ever been asked to do.
Session of 2026-08-27.

## What started it

A five-step plan for a dry run, and a blocker under step two: **there was no `dca-architect`
skill.** Only the vendored `icm-architect`, which still carries the five-form selection step this
method deleted and the instinct to consolidate toward one roof. Running it would have measured
ICM and reported the number as DCA's.

The operator then cut the scope hard: no GTM content, no product restructuring, no tooling layer,
no second test. Two components only, on the reasoning that everything past the first run is
speculation and the findings are what earn the right to plan it.

That cut removed four predictions from an earlier draft which were measuring the operator's
business rather than the architecture, which is what they would have reported on.

## What was settled

**The architect carries the nuances or they were never in the files.** That is the whole test.
Every rule here was argued into existence over two sessions, and an argument that only ever
convinced the people having it is worth nothing. The skill is the transmission attempt: the
umbrella and its floor, the charter, the board as an engine, the two documents, the naming rule,
proposes-never-settles, and the vocabulary that must not blur.

**The floor is stated as an acceptable outcome.** *An umbrella with one pipeline is just a
pipeline.* A tree that yields one wing is a tree DCA does not fit, and the skill says to report
that and stop. Inventing a second wing to make the shape come out right produces two charters
that are secretly one, which the consolidation test then has to undo.

**Adopt mode may create the method's own artifacts and nothing else.** No move, no rename, no
delete, no edit of anything that was there first. All of it goes to `templates/FINDINGS.md`,
which did not exist until today despite findings being named across the method since the founding
session.

**The gate cannot be live while a tree is being adopted.** Adoption is the act that creates the
territory the gate enforces, so a live gate refuses the charters that would authorise it. The
order is fixed: adopt, the operator grants, then install the harness. This was found by reading
the gate against the skill rather than by running either.

**A finding describes and does not perform**, one observation per entry, stated as a fact about
the tree, with the change named concretely enough to be refused. A finding with no proposed
change cannot be ruled on, only worried about. A declined finding stays filed, or it gets raised
again every session.

**A folder is named for the work done in it, never for the product it emits.** The operator's
observation, generalised: a workspace built around an output is a mill named after the flour. It
spreads because a folder named for its output cannot say what belongs in it, so it accumulates
whatever is adjacent and the boundary stops describing anything.

## The instrument

`tools/fingerprint.py`, built from the list `mechanics/ignition.md` already specified and never
exceeding it. Structure only: content is what makes a sweep expensive and reading it would put
the walk on a model.

It does two jobs with one mechanism. **Drift**, because structural decay is defined by nothing
arriving and last-touched age is the only signal for a failure whose entire symptom is absence.
And **adoption**, because a claim to have proposed rather than performed is then checkable: a
diff of additions only exits zero, and a removal or an edit exits one.

Two defects were caught by testing it rather than by reading it. It wrote its fingerprint inside
the tree it was fingerprinting, so every later diff opened with the record of itself, and it now
refuses that rather than filtering by filename. And it compared files only, so renaming an empty
folder was invisible, which is precisely the restructure the adoption check exists to catch.

## The first run, and why it is shaped as a contract

`HANDOFF.md` is an issued contract rather than a summary, because a session is a folder with a
mandate. It deliberately carries none of the conversation that produced the method.

Four rules keep it a measurement: the tree is not touched beforehand, the method is readable and
not writable, the expectations precede the run, and **the payload says what things are and never
what they are worth.** That last one cost an earlier draft a paragraph: it had warned that a
candidate tooling source would not transfer, which is a judgment about the work written into a
payload, pre-deciding the finding the run existed to produce.

The operator's correction was sharper than the rule: **re-aiming a body of work at a purpose its
method was not written for is the operation under test.** Ruling it out anywhere rules it out
everywhere, and there is nothing left to run.

Nine predictions, each falsifiable by looking. One to three test whether the umbrella and the
charter survived transmission. Four to eight test the smaller rules. Nine tests the gate against
work somebody actually wanted to do, which is the only test of a gate that means anything.

## The handoff carries its limits, and that was a correction

An earlier version of `../HANDOFF.md` stated one rule and over-applied it: the payload says what
things are and never what they are worth. That rule is about conclusions on the **subject**, and
it was being used to withhold what is known about the **instruments**, which is a different thing
entirely.

The operator's correction: do not keep the next session in the dark and hope for the best. A
tester who does not know a check is blind will record its silence as a pass. That is not
neutrality, it is a worse measurement, and the bias it produces runs toward false confidence
rather than away from it.

So `../handoff/` carries three references. **Known limits**: what has never run, what the gate
cannot see, what each tool is blind to, and which parts of the method have nothing behind them.
**Scoring**: three verdicts rather than two, and the rule that every failure has one of two
causes needing opposite repairs. **Continuing**: the conventions, the verification loop, and what
is deliberately not planned.

Two facts from `../rungs.md` turned out to change how the run must be conducted and were missing
from the mandate entirely. **Judgment is not a rung**, so a run where the model that produced the
work also decides whether it was good has voided its own result. And **the fetch rung has no
model behind it**, so a card written at that tier has nothing to run it and a report claiming
otherwise is a defect in the report.

The failure-diagnosis rule is the piece most likely to matter later. A prediction that fails does
so for one of two reasons: the skill was silent, or the skill said it and was ignored. The first
needs prose. **The second must not get prose**, because rewriting a sentence more emphatically is
the move that feels like progress and changes nothing: the layer that failed is the one that can
decline, so the rule has to move down into a check with an exit code or a refusal in the gate.

## What is still open

**Everything the run will decide.** Deliberately not planned. There is a restructure waiting and
passes sketched beyond it, and planning them now would mean guessing what the run says.

**The consolidation test cannot fully run yet.** Only an exercised charter counts, meaning one
amended at least once in response to something real, and every charter the architect writes is
unexercised. At this stage it catches only charters identical on their face. The skill states
that limit rather than overclaiming.

**No model has been tried at any rung.** Unchanged from yesterday and it is what the run finally
touches.

**The architect has never been invoked against a real tree.** Its artifacts were checked against
the gate in a scratch tree and behave. That is a shape test, not a run.
